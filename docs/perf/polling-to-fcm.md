# 알림 폴링과 푸시 전환 기록

알림 API의 반복 호출을 줄이기 위해 클라이언트 갱신 경로를 보완한 사례입니다.

## 문제와 변경

앱은 읽지 않은 알림 개수와 알림 목록을 주기적으로 조회했습니다. 서버에서는 [unreadCount](../../src/main/java/com/gatherit/api/notification/service/NotificationService.java)가 매번 저장소의 count 쿼리를 호출합니다. 데이터가 바뀌지 않아도 조회가 반복되므로, 쿼리 자체를 바꾸기보다 요청이 발생하는 조건부터 검토했습니다.

Android FCM HTTP v1 발송 경로와 앱의 원격 푸시 수신 캐시 갱신을 보완하고, 폴링 주기를 완화했습니다. 폴링은 푸시가 누락되거나 앱이 다시 열리는 경우에도 최신 데이터를 조회할 수 있도록 남겼습니다. 서버에 count 캐시를 추가한 사례는 아닙니다.

## 전후 비교에서 구분한 것

알림 개수와 목록 요청을 같은 범위로 묶어 전후를 비교했습니다. 전체 요청에서 알림 조회가 차지하는 비중과 실제 호출량은 별개로 해석해야 합니다. 이런 전후 관측은 사용자 활동, 앱 버전, 동시 변경의 영향을 함께 받으므로 푸시 도입만의 효과를 분리하지 못합니다.

## 당시 앱 소스에서 확인한 범위

검토한 앱 소스에서는 다음 동작을 확인했습니다. 현재 배포된 앱의 동작을 검증한 결과는 아닙니다.

- 읽지 않은 개수와 알림 목록에는 서로 다른 재조회 주기를 둡니다.
- 포그라운드 원격 푸시 수신 리스너는 알림, 일정, 투표 캐시를 무효화합니다. 로컬 예약 알림 종류는 이 갱신에서 제외합니다.
- unread-count가 증가했을 때 목록만 `exact: true`로 무효화해 unread-count 자신을 다시 호출하는 prefix 매칭 루프를 피합니다.
- 앱 상태에 따라 재조회를 명시적으로 멈추거나 주기를 더 늘리는 제안은 구현을 확인하지 못했습니다.

클라이언트 소스는 이 백엔드 저장소에 포함되어 있지 않습니다. 따라서 위 항목은 소스 확인 기록이며 이 저장소만으로 클라이언트 전체 동작을 재현할 수는 없습니다. 서버 전송 경로는 [FCM 발송기](../../src/main/java/com/gatherit/api/notification/service/FcmService.java), [APNs 발송기](../../src/main/java/com/gatherit/api/notification/service/ApnsService.java), [관련 ADR](../adr/0002-direct-apns-fcm-over-expo-push.md)에서 확인할 수 있습니다.

## 로컬 부하 테스트의 역할과 한계

k6, 백엔드, MySQL을 같은 로컬 머신에서 실행했습니다. 이 실험은 조회 패턴과 서버 포화가 측정값에 어떻게 나타나는지 확인하기 위한 것으로, 운영 용량이나 실제 동시 사용자 수를 검증하지 않습니다.

실험은 실제 앱의 조회 패턴을 흉내 내는 유형과, 목표 도착률을 높여 처리 한계를 관측하는 유형으로 나눴습니다.

- 조회 패턴에서는 가상 사용자별 첫 요청 시점을 분산하고, 지정 간격으로 반복 조회했습니다.
- 처리 한계는 도착률을 높이며 지연, 실패, 목표 도착률을 맞추지 못한 반복 수를 함께 확인했습니다.

폴링 패턴과 처리 한계는 다른 질문입니다. 같은 인증 사용자와 데이터를 반복 조회하는 테스트라면 데이터 분포와 사용자별 조회 비용도 운영과 다를 수 있습니다. 첫 요청을 동시에 시작하거나 응답의 `data.count`를 잘못 검사하면 서버 장애와 무관한 실패가 생길 수 있어, 테스트 결과를 서버 로그와 함께 읽어야 합니다.

재현한다면 격리된 로컬 서비스에서 합성 계정과 일정 데이터를 사용하고, 머신, DB 버전, 실험 시간을 함께 기록해야 합니다.

## 후속 검증

새 배포의 효과를 확인하려면 앱 빌드, 백엔드 소스, 관측 기간을 함께 기록하고 동일한 endpoint 정의로 다시 집계해야 합니다. 푸시 수신률, 사용자의 활성 시간, 폴링 실행 조건과 데이터 크기도 같이 확인합니다. 명시적인 백그라운드 pause와 더 긴 안전망 주기는 이 증거를 갖춘 뒤 별도로 검토할 작업입니다.
