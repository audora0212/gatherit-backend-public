# AI 일정 가져오기

공지나 대화에서 날짜, 시간, 장소를 추출해 일정 후보를 제시합니다. 사용자가 후보와 저장할 그룹을 확인한 뒤에만 캘린더에 등록합니다.

## 구현

1. 앱이 붙여넣은 텍스트나 자연어 요청을 `POST /api/ai/schedule/extract`로 보냅니다.
2. `AiScheduleService`가 사용량을 확인하고 `LlmExtractor`로 후보를 추출합니다. 모델 응답을 그대로 일정으로 쓰지 않고 제목과 시간 범위를 검증하고 중복 후보를 표시합니다.
3. 사용자가 고른 후보를 `POST /api/ai/schedule/commit`으로 보냅니다. 권한과 입력 범위를 다시 확인하고 기존 일정 등록 로직으로 저장합니다. 같은 사용자와 멱등 키로 재시도하면 기존 등록 결과를 반환합니다.

| 항목 | 소스에 포함된 동작 |
|---|---|
| 추출기 | `GeminiExtractor` 한 구현을 사용합니다. 다른 모델로 자동 전환하지 않습니다. |
| 검색 | `search=false`는 입력을 구조화하는 호출 한 번, `search`가 생략되거나 `true`이면 검색 근거 수집과 구조화 두 번입니다. |
| 날짜 | 현재 계약은 한국 시간 기준입니다. 별도 시간대 입력은 없으며 종일 후보는 날짜의 KST 시작과 끝으로 정규화합니다. |
| 응답 | 일정 후보, 중복 목록, 출처, 모델, 토큰 사용량과 쿼터를 반환합니다. 구체적인 날짜가 불명확한 후보에는 검토 필요 표시를 둘 수 있습니다. |
| 등록 | 그룹을 하나 이상 선택하고 최대 30개 일정을 등록합니다. 저장된 일정 ID를 응답합니다. |
| 사용량 통제 | 사용자별 일일 쿼터와 요청 제한을 적용합니다. 일일 횟수 계산을 위해 성공한 추출의 사용자 식별자와 시각을 기록합니다. |

## 검색과 직접 추출을 나눈 이유

착수 당시의 소규모 실호출에서는 한국어 붙여넣기 샘플 9개에 대해 상대 날짜, 연도 추론, 여러 일정 분리, 장소, 빈 결과를 확인했습니다. 이 샘플에서는 기대한 결과를 얻었지만, 정해진 소수 사례를 확인한 결과입니다. 사용자 입력에서도 모델이 날짜를 잘못 추론할 수 있습니다.

검색을 사용한 별도 5개 실험에서는 근거를 찾지 못해 답변을 보류한 사례와, 서로 다른 달력을 섞거나 실제로 확인되지 않은 날짜를 제시한 사례가 함께 나왔습니다. 그래서 출처를 보여주고 **사용자 확인 전에는 등록하지 않는 흐름**을 유지했습니다. 출처 표시만으로 모델 답변의 정확성을 보장할 수는 없습니다.

한 번의 검색 추출이 모델을 두 번 호출하므로 사용자별 추출 횟수, 공급자의 호출 한도, 과금은 별도로 봐야 합니다.

## 제약과 분리 검토

- 입력 DTO에 URL은 있으나 현재 서비스는 URL을 받아 서버에서 본문을 가져오지 않습니다. 웹검색 그라운딩과 임의 URL 수집은 다른 기능입니다.
- 이 코드에는 청구 API 연동, 다른 공급자로의 자동 전환, 독립 추출 서버가 포함되어 있지 않습니다.
- 외부 모델 요청은 일정 저장 트랜잭션 밖에서 수행합니다. 추출이 실패해도 수동 등록 경로는 유지됩니다.
- 분리를 검토한다면 외부 모델 호출만 옮기고, 사용자 권한, 쿼터, 후보 검증, 등록은 기존 API에 남기는 방향입니다. [ADR 0003](adr/0003-ai-service-msa-split.md)
